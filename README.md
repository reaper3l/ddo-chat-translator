# DDO 翻译助手 v3.0.2

**DDO（龙与地下城 Online）游戏聊天实时翻译助手**

盯着 DDO 的聊天框，把外国玩家说的英文实时翻成中文；也能把你想说的中文翻成
外国玩家习惯的英文缩写。翻译错了你改一次，它记住，下次遇到同样的句子直接用你的译法。

## 一、快速开始

```
cd ddo-translator
python -m pip install -r requirements.txt     # 只装一次
python main.py
```

第一次用只做四件事：

1. 点工具栏的 **区域**，拖拽框住游戏里的聊天框（松手后会立刻抓一帧给你看，确认框准了）。
2. 点 **设置** → 翻译 → 填 DeepSeek API Key（没有 Key 就先选 `mymemory` 免费试用）。
3. 点 **▶ 监听**，回到游戏。
4. 看到翻错的行，用鼠标选中它按 **F10**，改成正确的中文保存 —— 从此同样的句子直接用你的译法。

启动前建议先跑一次自检，它会告诉你环境、截图、OCR、接口哪一步有问题：

```
python tools/doctor.py          # 本地检查
python tools/doctor.py --api    # 顺便测一次真实翻译接口
```

## 二、它是怎么翻译的（决定了翻译质量）

每条聊天消息走这条链路，每一步都能在界面上看到结果：

| 步骤 | 做什么 | 为什么这么做 |
| --- | --- | --- |
| 1 | 截图 → **像素完全没变就跳过 OCR** | 聊天不动时不浪费 CPU |
| 2 | OCR（PP-OCRv5 mobile，对比度 1.2 倍） | 这是旧版反复试出来最稳的参数，动了会错行 |
| 3 | 同一视觉行的碎片合并、按 y 排序 | OCR 会把一行拆成两块 |
| 4 | 解析频道/玩家名/正文，续行接回上一条 | 真实格式是 `(小队):[小队] 名字: 正文` |
| 5 | 去重（指纹 + TTL + 前缀包含判断） | 同一句不重复翻译、不刷屏 |
| 6 | **术语保护**：术语换成 `{{TERM_n}}` 占位符 | 保证 reaper/shrine/favor/VON3 这类词不被模型乱翻 |
| 7 | 查**句子记忆** → 命中就直接用你的译文（不调接口） | 你改过的句子永远是你要的答案 |
| 8 | 调翻译接口（带最近 5 轮上下文 + 系统消息） | 上下文让"yes / same here"这种短句也能翻对 |
| 9 | 还原占位符 → 显示 | 占位符映射是**按消息独立**的，不会串位 |

顺带说明几个设计取舍：

- **术语表 1974 条**：我精选的 DDO 术语/俚语 + 从旧版搬过来的 1900 多条大词典。
  精选表优先级更高（旧表里 `tr=缠根`、`elite=精英` 这种会和精选冲突），
  你手动加的排最前。
- **不把整张术语表塞进提示词**（那样又慢又贵），只把术语换成占位符，再把你
  **确认过的**术语和句子偏好写进提示词，有数量上限。

## 三、自我学习：它到底怎么"越用越准"

学习分三层，从快到慢：

1. **整句记忆（立刻生效）**
   你按 F10 改过的句子，指纹记下来 → 以后遇到一模一样的句子直接显示你的译文，
   不花 API 费用。

2. **术语记忆（立刻生效）**
   「学习中心 → 待学习词」里列的是聊天里反复出现、术语表却没有的词（带出现次数和
   例句）。给它填个中文，它就进入术语表参与保护；也能在「词典」里随时增删。

3. **偏好学习（改得多了才生效）**
   同一句被你改了 N 次（默认 2 次，可在设置里调），或你标了"记住这句"，
   它就被写进 system prompt 的"我改过并希望保持的译法"，让模型对**新句子**
   也照着你的习惯来。

另外，术语表里没有的词会被自动统计（"待学习词"），模型原样返回英文的句子也会被
计数 —— 这两项就是"通过分析聊天内容自我优化"的入口。

学习数据都在 `data/memory.json`，可以备份、导出、导入，换电脑直接搬过去。

## 四、界面 / 快捷键

界面结构（参考了成熟翻译工具 LunaTranslator 的做法：深色主题 + 扁平按钮 + 分类设置）：

**默认就是"小巧模式"**：无边框窗口 + 工具栏只显示图标 + 界面缩放 1.0 —— 整个窗口
只占一小块，尽量不挡游戏画面。想回到标准窗口/带文字按钮：设置 → 显示与学习 里取消对应勾选。

**工具条可以折叠**：默认折叠，顶部只剩 `DDO ▸ ▶ — ✕`（约 160 像素宽）。
点标题「DDO」或 `▸` 展开全部按钮，再点一下收起（`▸`/`▾` 会跟着变）。

**背景可以透明**（设置 → 显示与学习 → 背景透明，三档）：

| 模式 | 效果 |
| --- | --- |
| 不透明（默认） | 正常深色面板 |
| 整窗半透明 | 整个窗口（含文字）按 `alpha`（0.5~1.0）变淡，适合半遮半掩地看 |
| **只透明背景** | 用颜色键把窗口底色变全透明，**文字和按钮保持完全不透明** —— 屏幕上只剩译文浮在游戏画面上 |

「只透明背景」依赖 Windows 的 `-transparentcolor`（Tk 8.6 自带）；万一系统不支持，
程序会提示并自动按不透明处理。配合折叠工具条 + 关掉状态栏，可以做到屏幕上几乎只有译文
（状态栏关掉后，错误提示仍会以红字显示在聊天区里，不会丢信息）。

- **顶部工具条**（紧凑，整行约 300 像素）：品牌名 + 主按钮「▶ 开始监听」/「■ 停止监听」
  （运行中变红）+ 图标按钮（⊞ 区域 / ◎ 测试 / ⇄ 中译英 / ✎ 纠错 / ▤ 词典 / ✦ 学习 / ⚙ 设置）
  + 窗口按钮（— 最小化 / ✕）。每个按钮都有鼠标悬停提示，提示里带快捷键和说明。
  没点监听时按钮就是蓝绿色的"开始监听"，不会误显示成运行中。
- **底部状态栏**：左边一个状态圆点（运行中绿色 ●，停止灰色 ○）加状态文字
  （成功绿 / 警告黄 / 错误红），右边是 `待译 · 缓存 · 调用 · 记忆 · 错误` 计数。
- **中间聊天卡片**：带 1px 描边的内嵌面板，右上角是细滚动条。
- **设置**：打开一个小的"设置中心"，列出 翻译 / 监控 / 显示与学习 / 外观 / 关于；
  **每一项都在自己的独立窗口里编辑**（内容再多也不会被窗口高度挤掉），
  窗口底部固定「保存并关闭 / 应用 / 测试连接（仅翻译页）」；已打开的窗口再点会抬到前面。
  「关于」页可以直接打开数据目录、日志文件、术语表。
- **外观**：全暗色主题，配色统一；界面字号、界面缩放（0.8~1.25）在 外观 → 基础 里调，
  聊天字体则逐项设置（频道前缀/玩家名/译文/系统消息/原文/时间戳）。

**界面只有暗色主题**（不做浅色切换：切换会留下"半白半黑"的残留，而且这个工具本来就是贴在
游戏画面上用的）。聊天区底色是独立的「窗口底色」，要和界面底色不同就在 外观 → 基础 里改。

暗色下的可读性已经调过一轮：面板色、描边、次要文字都提亮了一档，次要文字（英文原文/时间戳）
默认色从 `#6b7280` 提到 `#98a1ab`。如果你自己把字色调暗了导致看不清，去 外观 里改回来
（正文默认色建议 `#8ef58e`，频道色建议 `#7ee787` 这类亮色）。

两个可选的界面形态（设置 → 显示与学习，勾选后保存即可，不用重启）：

| 开关 | 效果 | 注意 |
| --- | --- | --- |
| **无边框窗口**（默认开） | 去掉系统标题栏，改由工具条拖动移动、贴边 6 像素内拖动缩放、右下角 `◢` 缩放；此时工具条右侧会多一个「—」最小化按钮 | Tk 的限制：无边框窗口不会出现在任务栏/Alt+Tab。程序做了保护：最小化时会先恢复系统边框再最小化，保证能从任务栏找回；取消勾选就回到标准窗口 |
| **工具栏只显示图标**（默认开） | 按钮变成纯图标（`⊞ 区域` → `⊞`），整行窄一半；鼠标悬停有完整说明 | 图标是矢量符号，不依赖图片资源 |

**翻译窗口的显示格式和游戏聊天框一模一样**（频道、玩家名 1:1 还原，只有玩家说的话换成中文）：

```
(小队): [小队] Sckham: 兄弟们，你们在 Steam 上玩别的游戏吗？
(小队): [小队]    Kendra Estleton 加入了你的队伍        ← 系统消息原样显示，不翻译
(战利品): Dorqeth 将 Jeweled Key 从 宝箱 中取出         ← 战利品行也照游戏显示
(小队):   你的队友 Kendra Estleton 已死亡
(小队): [小队] Sckham: https://store.steampowered.com/…  ← 链接完整保留，不会被翻译
```

规则：

* 前缀（`(小队): [小队] ` 这种）按 OCR 读到的原样显示，颜色按频道区分；
* 玩家名加粗显示，后面接翻译后的中文；
* 长消息被游戏换行显示时，翻译窗口里是一条完整消息（自动折行），不会拆成好几条；
* 系统消息（组队/死亡/断线/战利品）和游戏一样原样显示、不送翻译，但会作为上下文
  帮助模型理解（比如"你的队友X已死亡"能让上下文更连贯）；
* **显示顺序严格等于游戏里的顺序**：就算玩家发言要等接口返回，中间夹着的系统消息
  也会排队等它，不会插到前面去；
* 想关掉系统消息：设置 → 监控 → 显示系统消息（或按频道分别关）；
* 想在译文后面看到"记忆命中/缓存/词典直译"这类来源标注：设置 → 显示与学习 → 标注来源
  （默认关闭，保持和游戏一样的干净外观）。

**外观可以逐项自定义**（设置 → 外观，带实时预览）：

| 对象 | 可调 |
| --- | --- |
| 频道前缀 | 字体、字号、粗细、斜体、底色、边框宽度（**颜色在下面按频道设，不在这里**） |
| 玩家名 / 翻译正文 / 系统消息 / 英文原文 / 时间戳 | 字体、字号、粗细、斜体、颜色、底色、边框宽度，以及**「颜色跟随频道颜色」**开关 |
| 每个频道（小队/队伍/公会/常规/公共/悄悄话/战利品） | 各自的颜色；想统一就用「全部设为同一色」 |
| 全局 | 基础字体、基础字号、窗口底色、正文默认色（「翻译正文」颜色留空时用它） |

**翻译正文默认"跟随频道颜色"**：小队绿、公会蓝、常规黄、公共橙、悄悄话粉、战利品灰 ——
和游戏里整行同色一致。实现方式是为每个频道派生一份正文标签（`body_小队` 这类），
渲染时按当前行的频道选用。取消勾选后颜色输入框恢复可用，可以给整段正文定一个固定色；
这个开关对玩家名 / 系统消息 / 英文原文同样开放（默认只有正文开启）。

说明：颜色留空 = 用默认（频道前缀用该频道颜色，正文用正文默认色）；字号填 0 = 跟随基础字号，
填负数 = 比基础小几号。**关于"描边"**：Tk 的文本框没有字形描边能力，这里用
「底色 + 边框」实现同样的视觉效果；如果一定要逐字描边，需要把显示层换成 Canvas 重画，
可以后面单独做。

| 快捷键 | 作用 |
| --- | --- |
| F8 | 开始 / 停止监听 |
| F9 | 把剪贴板里的中文翻成英文 |

| F5 | 测试识别（抓一帧 → 显示画面和识别结果） |

工具栏：**区域 · 测试 · 中译英 · 纠错 · 词典 · 学习 · 设置 · 退出**。
右键主界面还有一份同样的菜单。

## 五、常见问题

### 监听时游戏卡顿怎么办（v3.0.2 起已默认优化）

监听需要持续截图 + OCR，处理不好会和游戏抢 CPU。程序现在做了四件事：

| 手段 | 作用 |
| --- | --- |
| **画面没变化就跳过 OCR** | 聊天框大部分时间是静止的。先用 48×48 灰度缩略图 + 容差比对，判定没变就整帧跳过 —— 这是最省 CPU 的一招（状态栏「跳过 N」就是省下的次数） |
| **只识别变化的那几行**（v3.0.3） | 变化只发生在中下部时（滚动/新消息的常见情况），只把那一小条送去 OCR，上面不变的部分沿用上一帧的识别结果 —— OCR 时间降到 1/4~1/5。每 20 帧或变化过大时自动整帧识别一次校准 |
| **程序用低于游戏的 CPU 优先级**（v3.0.3） | 整个程序（含 OCR 线程）降到 `BELOW_NORMAL`，游戏需要 CPU 时永远先拿到；监听是后台任务，慢一点没关系 |
| **OCR 线程数限制（默认 2）** | onnxruntime 默认吃满所有核心、线程还会忙等，会和游戏抢 CPU；现在限制线程数，并把等待策略设为 `OMP_WAIT_POLICY=PASSIVE` |
| **空闲自动放慢** | 连续 5 帧没变化后，截图间隔自动 ×2（最长 3 秒），有变化立刻恢复 |
| **放大倍数 2 → 1.5** | 每帧 OCR 时间约省 20%（识别质量基本不变） |

都可以在 **设置 → 监控** 里调：截图间隔、OCR 线程数、OCR 放大倍数、画面没变化时跳过 OCR、空闲放慢。
建议保持：间隔 1200ms、线程 2、放大自动。**如果游戏仍然卡，把 OCR 线程数降到 1**（最省 CPU，
OCR 会慢一点但聊天完全够用）。

想看具体数字，在你机器上跑一次性能自检（会打印截图 / 变化检测 / 整帧与局部 OCR 的耗时）：

```
python tools\perf_check.py
```

另外两点：① 游戏请用**窗口化 / 无边框窗口**模式，独占全屏下截图会强制切换显示模式，更容易卡；
② 如果你把「背景透明」设成了「只透明背景」而机器较老，DWM 合成也会多花一点资源，卡的话先关掉。

### 翻译质量怎么继续调（信达雅）

三个入口，从快到慢：

1. **纠错（F10）**：哪句不顺眼就改成你要的译法。同一句以后**直接用你的译文**，
   改到 2 次以上还会作为"我偏好的译法"写进提示词，影响**新句子**。
2. **术语表**：只保护真正的游戏术语（reaper/shrine/favor/abandon/share…）。
   注意：**普通英文单词不做保护**——旧版大词典里有 `will→意志`、`die→死亡` 这类条目，
   一旦被保护，模型就只能逐词填空，会出现"意志 只是在 死亡 驯服中"这种碎句，
   所以程序会把常见词和 1~2 字母的旧条目自动过滤掉。
3. **提示词**：`app/prompt.py` 里的 `TRICKY_EXAMPLES` 是易错句范例（turn in=交任务、
   i never die=我从来没死过、clicked enter while showing normal…），
   `SLANG_TABLE` 是缩写对照表。想调风格（更口语/更简短/换称呼）改这里最快。

改完想立刻验证某几句，用对照表模式（会真的调一次接口）：

```
python tools\trace.py --text "i never die" --text "thanks for now, will just die in taming"
python tools\trace.py --file 聊天记录.txt        # 每行一条，最后会打印 原文 → 译文 对照表
```

**框选的位置和实际抓到的画面不一致？**
这是 DPI 坐标问题：Windows 会把 Tk 报告的坐标按显示缩放"虚拟化"
（2560×1440 的屏在 125% 缩放下，另一套 API 只看得到 2048×1152），
而截图可能是另一套像素空间，两边就对不上。

程序现在做三层处理：① 启动时按显示器感知 DPI；② 每次截图前显式把截图线程
设成物理像素模式；③ **实测校正** —— 抓一张整屏，跟 Tk 报的屏幕尺寸相除算出
真实比例，不一致就自动换算框选坐标（状态栏会提示"截图坐标已自动校正 x0.800"）。

如果还是偏，按顺序做：

1. 点 **测试**，预览图顶部会显示「屏幕尺寸 / DPI / Tk缩放 / 截图空间 / 换算比例」；
2. 跑 `python tools\capture_probe.py`：它会存一张整屏标注图
   `data\probe_overlay.png` —— 红框是你框选的坐标，黄框是换算后实际截取的位置。
   哪个框套住聊天框，一眼就能看出来；
3. 两种模式都试一次：把 `data/config.json` 里的 `dpi_mode` 改成 `"legacy"`
   （旧的不感知 DPI 行为）后重启，不行再改回 `"auto"`。

另外确认游戏跑的是窗口化 / 无边框窗口模式，而不是独占全屏。

**翻译显示的是英文原文？**
说明接口没成功。看状态栏的红色提示：没填 Key / Key 无效 / 余额不足 / 超时都会写明。
填了 Key 还是失败，跑 `python tools/doctor.py --api` 定位。

**想一步步看"这句话到底走到哪一步失败了"？**
```
python tools\trace.py                          # 抓当前区域，走完整流程并逐步打印
python tools\trace.py --text "(小队): [小队] Dorceth: elite right?"
```
它会依次打印：引擎是否可用 → OCR 原始行 → 解析结果（聊天还是系统消息）→
术语保护后的文本 → 接口返回 → 最终显示的样子。哪一步不对一眼就能看出来。

**一直没有输出？**
① 没点"监听"；② 区域没框对（点"测试"看识别结果）；③ 频道被关掉了（设置 → 监控）；
④ OCR 模型第一次加载要几秒，状态栏会提示。

**费用大概多少？**
DeepSeek 每条约几分钱到几毛钱（取决于长度），术语命中和整句记忆不花钱。
想不花钱就把引擎切到 `mymemory`（免费在线，质量一般）或 `offline`（只翻术语）。

**想让它更快？**
设置 → 翻译 → 模式选 `fast`；或把截图间隔调大；`skip_identical_frame` 保持打开。

**要打包成 exe？**
```
pyinstaller --noconfirm build.spec
```
必须用 onedir（`build.spec` 已经是），不要用 onefile —— 旧版在 onefile 下
打包 rapidocr 的动态库会崩（exit code 3221225477）。

**数据在哪？删了会怎样？**
`data/` 下：`config.json`（设置，含明文 Key）、`memory.json`（学习库）、
`cache.json`（翻译缓存）、`logs/app.log`（日志）。删掉 `memory.json` 等于
清空学习成果，删掉 `cache.json` 只是下次重翻一遍。备份直接整个 `data/` 目录拷走。

## 七、相对旧版修掉了什么（都是旧版真实存在的坑）

| 旧版问题 | 现在 |
| --- | --- |
| `messagebox/filedialog/Toplevel/ttk` 没导入，"保存记录/关于/纠错/词典"一点就 NameError | 全部正常导入，并且加了 `tools/check_names.py` 在提交前扫一遍 |
| `translate_by_mode` 给所有引擎传 `on_chunk`，只有 DeepSeek 支持 → 免费/百度/豆包模式全部原样返回英文 | 引擎接口统一，三种引擎都实测可用；没有 Key 自动降级到离线并提示 |
| 术语占位符映射挂在全局单例上，异步翻译时会互相覆盖 → 术语串位 | 映射按消息独立返回，回归测试 `test_mapping_is_per_message` 守住 |
| 每条消息编译 ~1900 个正则、做 1900 次替换 | 改成"词表 + 1~4 元组查表"，一次扫描搞定，顺带收集生词 |
| 反复启停监听会累积截图/翻译线程，多个线程抢同一个队列 | 每次启动都是新线程，停止时 join；界面只通过队列收结果 |
| 后台线程直接写 Tk 控件 | 所有 UI 更新都回到主线程 |
| `_hidden` 从未初始化、贴边 geometry 少写 `+` | 这套没人用的贴边逻辑整块删掉了 |
| 消息里出现中文就被正则从头砍掉，中文消息直接消失 | 指纹保留汉字；中文原文直接显示，不送接口 |
| 人名映射/预处理规则对话框改完不落盘，重启就没了 | 统一写进 `data/memory.json`，原子写 |
| 专有名词/翻译后修正写进 A 文件、启动读 B 文件 → 数据丢失 | 学习库只有一份文件，读写同一个路径 |
| 相对路径读写 `config.json`，换工作目录就失灵 | 所有路径基于程序目录 |
| 每条消息都写一次磁盘缓存 | 内存缓存 + 定时落盘，原子写 |

## 八、还没做 / 你可以继续加的东西

- 全局热键（不聚焦窗口也能按 F10）需要额外装 `keyboard` 库，我没引入新依赖。
- 批量翻译（一次把多条新消息丢给模型）能省接口调用，但会牺牲"一条翻好就显示"的实时感，
  现在保持逐条 + 单线程顺序，符合聊天场景。
- 说话人名字的固定译名映射还没做（人名统一交给模型保持原样）。
