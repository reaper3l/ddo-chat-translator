# 本地翻译平台 · 接口说明

DDO 翻译助手可以把自己变成一台**只在本机运行**的翻译服务：

* 你写的脚本、别的程序、以及本程序的**插件**都能通过 HTTP 调用翻译；
* 用的是界面里**同一套**术语表、记忆库和缓存 —— 界面翻过的句子，插件再问一次
  不会重复花钱；插件纠正过的译法，界面里也立刻生效；
* 插件**拿不到**你的 DeepSeek API Key，它只能通过平台转发，花费记在平台账上。

> 默认是**关**的。打开：`设置 → 平台 / 插件 → 启用本地翻译平台 → 立即应用`。

---

## 一、它在哪里

* 地址：`http://127.0.0.1:<端口>`，默认端口 `8765`。
* **只监听 127.0.0.1**：同一台电脑能连，局域网/互联网上的别的机器连不上。
* 端口被占用时会自动往后找（8765 → 8766 → …），实际端口在设置页和
  `/v1/health` 里都能看到。
* 不想开界面也可以纯命令行跑：

  ```bat
  DDO翻译助手.exe --serve                 :: 用配置里的端口
  DDO翻译助手.exe --serve --port 8765     :: 指定端口
  ```

---

## 二、认证

除了 `/v1/health` 和 `/v1/capabilities`，所有接口都要带**该插件的令牌**：

```
Authorization: Bearer <令牌>
```

令牌在 `设置 → 平台 / 插件` 里，每个插件一行，点「令牌」就能复制
（或者直接看 `data/platform.json`）。怀疑某个插件乱来，点「重置令牌」，
旧令牌立刻作废。

**权限（scopes）** —— 新启用的插件默认只有前两项，其余要你手动勾：

| scope | 含义 |
|---|---|
| `translate` | 翻译（英→中 / 中→英） |
| `batch` | 一次翻多条（能合并成一次请求，更省） |
| `terms:read` | 读术语表 / 词典 |
| `terms:write` | 往本机词典加词（**会改动你的词典**） |
| `feedback` | 提交纠错（本机学习，立即生效） |
| `stats` | 查看用量统计 |

## 三、接口

所有请求/响应都是 JSON（UTF-8）。错误响应长这样：

```json
{"ok": false, "error": "中文说明", "code": "quota_exceeded"}
```

| 状态码 | code | 什么时候 |
|---|---|---|
| 400 | `bad_request` | 参数不对 / 请求体不是 JSON |
| 401 | `unauthorized` | 没带令牌或令牌不对 |
| 403 | `forbidden` | 插件被停用，或没这个 scope |
| 404 | `not_found` | 没有这个端点 |
| 413 | `too_large` | 请求体太大（上限 2MB） |
| 429 | `quota_exceeded` | 今天这个插件的翻译次数用完了 |
| 500 | `internal_error` | 平台内部出错 |

### 1. GET /v1/health（免令牌）

```json
{"ok": true, "service": "ddo-translator-platform", "version": "3.0.35",
 "host": "127.0.0.1", "port": 8765, "uptime_seconds": 128,
 "engine": "DeepSeek(deepseek-chat)", "engine_available": true, "plugins": 2}
```

### 2. GET /v1/capabilities（免令牌）

版本、引擎、术语条数、能力声明（支持哪些方向、批量、纠错、单条字数上限）。

### 3. POST /v1/translate（scope: translate）

请求：

```json
{"text": "omw, need heals for shroud",
 "direction": "auto",
 "context": ["前面那句原文（可选，最多几条）"],
 "speaker": "Guihuo", "channel": "小队"}
```

* `direction`：`auto`（按内容判断）| `en2zh` | `zh2en`。

响应：

```json
{"ok": true, "zh": "马上到，幽影堡需要治疗",
 "source": "omw, need heals for shroud",
 "direction": "en2zh",
 "note": "缓存",
 "cached": true,
 "api_calls": 0,
 "elapsed_ms": 3,
 "terms": [["shroud", "幽影堡"]]}
```

> `text` 超过 `platform_max_chars`（默认 4000）会被截断，并在结果里带
> `"truncated": true`。`api_calls: 0` 表示本地命中，没花钱。

### 4. POST /v1/translate/batch（scope: batch）

```json
{"texts": ["omw", "need heals", "ty"], "direction": "auto", "context": []}
```

```json
{"ok": true, "engine": "DeepSeek(deepseek-chat)",
 "results": [ {"...": "同 /v1/translate"}, {}, {} ]}
```

多条会**合并成一次接口请求**（受设置里的「一次翻几条」控制），所以比逐条调更省钱。

### 5. POST /v1/feedback（scope: feedback）

把「这句话应该这么翻」告诉程序，本机立刻学会（等价于界面里的 F10 纠错）。

```json
{"source": "pop side", "before": "流行音乐那边", "after": "位面监狱那边",
 "remember": true}
```

```json
{"ok": true, "learned": "phrase", "applies": "本机立即生效"}
```

### 6. GET /v1/terms?q=shroud（scope: terms:read）

```json
{"ok": true, "term": "shroud", "zh": "幽影堡", "found": true, "mine": false}
```

### 7. POST /v1/terms（scope: terms:write）

```json
{"term": "FoD", "zh": "冲突基地"}
```

### 8. GET /v1/stats（scope: stats）

这个插件今天的用量 + 配额 + 是否还剩，以及平台累计统计
（`api_calls` / `cache_hits` / `memory_hits` / `dict_hits` …）。

### 9. GET /v1/plugins（scope: stats）

本机装了哪些插件、是否启用、有哪些动作、各自的权限。

## 四、命令行快速试

```bat
:: 翻一条（走界面那套缓存和词典）
DDO翻译助手.exe --translate "omw"
DDO翻译助手.exe --translate "马上到" --direction zh2en
DDO翻译助手.exe --translate "omw" --json
```

```
:: 直接打 HTTP
curl -H "Authorization: Bearer <令牌>" -H "Content-Type: application/json" -d "{\"text\":\"omw\"}" http://127.0.0.1:8765/v1/translate
```

仓库里还带了一个示例客户端：`tools\platform_client.py`。

```bat
python tools\platform_client.py health
python tools\platform_client.py translate "omw"
python tools\platform_client.py batch "omw" "ty" "need heals"
python tools\platform_client.py terms --q shroud
python tools\platform_client.py plugins
```

（不指定 `--token` 时，它会自己去 `data\platform.json` 里找已启用的插件令牌。）

## 五、写一个插件

插件就是 `plugins\` 下的一个子目录，里面至少有一个 `manifest.json`。
宿主（翻译器）会**按需拉起**它的进程，把请求用 JSON 从 stdin 喂进去，
再从 stdout 把 JSON 收回来。

```
plugins\
  guide-hanhua\           <- 一个插件一个目录
    manifest.json         <- 必须有
    plugin.py             <- 入口
    README.md
```

### manifest.json

```json
{
  "id": "guide-hanhua",
  "name": "DDO 网站攻略汉化",
  "version": "0.1.0",
  "description": "抓一页英文攻略，调用翻译平台，生成中英对照的 Markdown",
  "author": "你的名字",
  "entry": "plugin.py",
  "actions": [
    {"id": "translate-clipboard", "name": "汉化剪贴板里的攻略文本"},
    {"id": "translate-url", "name": "汉化一个攻略网址", "desc": "会先问你要 URL"}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `id` | 只允许小写字母、数字、`.`、`_`、`-`，用来认人（令牌按它发） |
| `entry` | 相对插件目录的入口文件；`.py` 会用 Python 跑，其它直接执行 |
| `command` | 想完全自己控制命令行时用它（数组），`{plugin_dir}` 会替换成插件目录 |
| `actions` | 右键菜单「插件」里出现的动作；每个动作一个 `id` |

> `entry` / `command` 二选一。**打包版**跑 `.py` 插件需要系统里有 Python 3；
> 不想依赖 Python 就做成 `.exe`（`entry` 指向它即可）。

### 进程协议

宿主启动命令：`<entry 或 command> <action_id>`，工作目录 = 插件目录。

**stdin**（读一次就 EOF）：

```json
{"version": 1, "action": "translate-url",
 "payload": {},
 "platform": {"base_url": "http://127.0.0.1:8765", "token": "<你的令牌>"},
 "plugin": {"id": "guide-hanhua", "name": "DDO 网站攻略汉化", "dir": "..."}}
```

**stdout**（最后一段 JSON，前面可以有日志）：

```json
{"ok": true,
 "message": "已生成 12 段译文",
 "text": "给用户看的正文（可选）",
 "output": {"任意结构": "给程序用的结果"},
 "files": ["D:\\生成的攻略.md"]}
```

环境变量里也带了一份（图省事可以直接读环境变量）：
`DDO_PLUGIN=1`、`DDO_PLATFORM_URL`、`DDO_PLATFORM_TOKEN`。

**规矩**

* 超时会被**强杀**（含子进程）；超时时间由宿主决定（默认 10 分钟）。
* 插件崩了不会影响翻译器 —— 宿主只显示错误和插件最后几行日志。
* 插件**不要**自己保存 API Key；要翻译就调 `platform.base_url`。
* 结果里 `text` 会显示在程序里的一个窗口中，`files` 会列出来。

## 六、费用与安全

* **每日配额**：每个插件每天最多消耗 `platform_daily_quota` 次真实接口调用
  （默认 500，本地命中和缓存不计数）。超了返回 429，不会再偷偷花钱。
* **单条上限**：`platform_max_chars`（默认 4000）。
* **插件永远拿不到 API Key**：Key 只在程序进程里。
* **只监听 127.0.0.1**：外网/局域网访问不到。
* **默认全关**：平台默认不开，插件默认停用、默认只有 `translate` 权限。
* 插件请求的内容**默认不会**参与「公共词典 / 参与改进」回流。

## 七、常见问题

**Q：端口被占用？**
换个端口再点「立即应用」，或者关掉占用它的程序。程序也会自动往后找一个能用的。

**Q：插件点了没反应？**
先看 `设置 → 平台 / 插件` 里那个插件是不是「已启用」，再看它的「权限」够不够；
然后在右键菜单「插件」里点它的动作，结果窗口里会写清楚错误原因。

**Q：怎么彻底关掉？**
把「启用本地翻译平台」取消勾选，点「立即应用」；插件全部取消启用。
